# Проверки проекта

## Мягкое автоодобрение — 01.11.2026

- Полный прогон `pytest -q -p no:cacheprovider --tb=short` с настоящим PostgreSQL 17: **173 passed in 33.76s**, без пропусков.
- Ruff и форматирование: все проверки прошли, 28 Python-файлов.
- Docker-образ `vgspu-love-bot:auto-approve` собран. Отдельный запуск установленного пакета в Linux подтвердил наличие `data/blocked_words.txt`, автоодобрение признания с именем, блокировку разделённого пунктуацией мата и отсутствие ложного совпадения для «педикюр»/«подстрахуй».
- Проверены обычные признания, имена, @username, эмодзи, Unicode, разделённые буквы, подмены латиницей, границы слов, редактируемые списки и ручной режим. PostgreSQL-сценарий подтверждает путь «признание с именем → автоодобрение без модератора → очередь → публикация».
- Новое значение `AUTO_APPROVE_ENABLED` по умолчанию — `true`. Явное `false` в окружении хостинга по-прежнему возвращает ручную проверку. Схема БД не менялась.
- Telegram API в тестах заменён записывающей сессией: реальным людям и каналам ничего не отправлялось. Рабочая база пользователя не использовалась. Тестовый PostgreSQL после проверки остановлен.

## Публикация и диагностика — 31.10.2026

Проверки выполнены локально. Рабочая база пользователя не подключалась и не изменялась.

Дополнение от 31.10.2026: добавлена диагностика ошибок Telegram при старте. Прогон `pytest -q -m 'not postgres' --tb=short`: **97 passed, 49 deselected**. Среди новых проверок — безопасное описание `chat not found`, недостаточных прав и неверного токена, указание этапа/метода запроса, остановка при недоступном канале и продолжение запуска после ошибки необязательного меню команд. Тексты и секретные параметры не попадают в диагностические поля. Ruff прошёл для 27 файлов. PostgreSQL-тесты в этом дополнении не перезапускались: изменений схемы или транзакций нет. Основной прогон: Windows, Python 3.12.10, SQLAlchemy/asyncpg и настоящий PostgreSQL в одноразовом Docker-контейнере. Проверены обе ветки модерации, конкурентные операции, идемпотентность, лимиты, права, личная история, уведомления, удаление и сроки хранения. Миграционные тесты проверяют сохранность чужой таблицы в `public` и одобренного предложения при обновлении схемы с 0001 до 0002.

Telegram-сценарии выполняются через aiogram Dispatcher с настоящими моделями обновлений. Сетевой Telegram API заменён записывающей тестовой сессией; реальным пользователям и каналам ничего не отправлялось. Проверены публикация только подтверждённого текста, запрет публикации pending/rejected, выключенный режим, ручная отправка старого approved, конкурентные worker, сохранённая пауза, 429/retry_after, ошибки прав, неизвестный результат сети/сервера, сбой фиксации после отправки, восстановление после перезапуска и ручная сверка. Посторонние каналы и `@username` блокируются до сетевого запроса. Для рабочего запуска нужны реальные `BOT_TOKEN`, `DATABASE_URL`, `ADMIN_IDS`, `CHANNEL_ID` и `PUBLICATION_ENABLED=true`.

GitHub Actions настроен на push для Python 3.11/3.12/3.13; результат удалённого запуска следует смотреть во вкладке Actions. Временный PostgreSQL после проверки остановлен. Собранный образ доступен локально как `vgspu-love-bot:publication`. Исходная версия предложки была проверена 30.10.2026: 111 тестов; текущий набор включает ещё 21 проверку публикаций и обновления схемы.
