# Публикация в Telegram-канал

## Включение

1. Добавьте бота в администраторы канала с правом «Публикация сообщений» (`can_post_messages`). Это право предусмотрено [Telegram Bot API](https://core.telegram.org/bots/api#chatmemberadministrator).
2. В переменных окружения хостинга задайте:

   ```dotenv
   CHANNEL_ID=-1001234567890
   PUBLICATION_ENABLED=true
   PUBLICATION_INTERVAL_SECONDS=60
   AUTO_APPROVE_ENABLED=false
   ```

   Замените ID примером вашего канала. Нужен отрицательный **числовой ID**, а не `@username`. Его можно получить из `channel_post.chat.id` в Telegram Bot API после добавления бота и публикации сообщения в канале. При использовании `getUpdates` временно остановите polling бота. ID и токен — разные настройки; токен храните только в окружении.
3. Обновите код, выполните `alembic upgrade head`, перезапустите бота. В Docker и на Bothost миграцию запускает `deploy/start.sh`. Новая миграция `0002` создаёт только две новые таблицы, сохраняя предложения и другие данные.
4. Откройте `/admin` → «⚙️ настройки». Проверьте канал, включённый режим и паузу. При старте приложение проверяет тип чата и право публиковать: группа или бот без нужного права не проходят проверку.

Если оставить `PUBLICATION_ENABLED=false`, бот продолжит работать как предложка. Наличие одного `CHANNEL_ID` не включает отправку.

## Как работает

`предпросмотр → подтверждение автора → pending → модератор одобряет → approved + очередь → Telegram → published`.

Новые одобренные предложения автоматически ставятся в очередь в одной транзакции с решением. В канал отправляется только подтверждённый `normalized_text`, без заголовка «люблю», имени, Telegram ID, подписи автора и модераторских кнопок. Предпросмотр ссылок выключен, текст не интерпретируется как HTML/Markdown.

При успехе Telegram возвращает [Message](https://core.telegram.org/bots/api#sendmessage). Бот сохраняет message ID, время публикации и аудит. Автор видит «опубликовано» в своей истории; число публикаций отображается в статистике.

При включённом `AUTO_APPROVE_ENABLED` строгий безопасный whitelist также проходит в очередь. Для ручной проверки всех текстов оставьте этот параметр `false`.

Существующие одобренные записи **не публикуются массово** при включении режима: откройте «✅ одобренные» и нажмите «📤 опубликовать» у нужной записи. Повторное нажатие не создаёт второе задание. «📤 публикации» показывает необработанные задания и проблемы отправки.

`PUBLICATION_INTERVAL_SECONDS` задаёт паузу между запросами отправки. Значение сохраняется через общий PostgreSQL-ограничитель, поэтому перезапуск не сбрасывает паузу. Второй worker не отправляет то же задание параллельно. Очередь хранит целевой ID канала: после смены `CHANNEL_ID` старое задание останавливается с `ChannelChanged`, пока модератор явно не разрешит повтор в новый канал.

## Ошибки и защита от дублей

| Состояние задания | Действие |
| --- | --- |
| `queued` | ожидает своей очереди и паузы |
| `sending` | намерение сохранено в БД, идёт запрос Telegram |
| `published` | Telegram подтвердил отправку, message ID записан |
| `failed` | Telegram явно отклонил запрос либо настройки канала изменились; нужен ручной повтор |
| `uncertain` | неизвестно, появился ли пост; сначала проверьте канал |

При `429` Telegram сообщает [retry_after](https://core.telegram.org/bots/api#responseparameters); бот переносит отправку и повторяет её автоматически. При отсутствии прав/неправильном запросе исправьте настройки, затем откройте «📤 публикации» → «повторить публикацию».

У Bot API `sendMessage` нет пользовательского ключа идемпотентности. Если соединение оборвалось после принятия поста Telegram, или процесс остановился до фиксации результата в БД, невозможно надёжно отличить отправленный пост от неотправленного. Поэтому сетевые ошибки, тайм-ауты, ответы сервера с неопределённым результатом, сбой БД после отправки и незавершённое `sending` после перезапуска дают **`uncertain` без автоматического повтора**. Это осознанная остановка, а не гарантия доставки «ровно один раз».

Порядок сверки:

- **Пост уже есть в канале.** Возьмите номер сообщения из ссылки на пост и выполните в личном чате бота: `/published НОМЕР_ПРЕДЛОЖЕНИЯ MESSAGE_ID`. Пример: `/published 184 731`. Команда доступна только администраторам, принимает только `uncertain` и фиксирует результат в аудите без повторного запроса отправки. Номер сообщения вы подтверждаете вручную: бот не сверяет чужую ссылку автоматически.
- **Поста нет.** Нажмите «повторить публикацию», затем «поста нет — повторить». Повтор направляется в текущий `CHANNEL_ID`. Если ошибочно подтвердить отсутствие уже существующего поста, возможен дубль.

Кнопки и команду проверяет общий контроль администраторов и сервисный слой. Сетевые ошибки не отменяют одобрение. Тексты/токены/полные ответы Telegram не выводятся в логи; код ошибки доступен в карточке администратора.

## Удаление данных

`/delete_my_data` и автоматическое удаление по сроку хранения удаляют записи, аудит и задания из базы. Неотправленные задания отменяются. **Посты, уже появившиеся в Telegram-канале, остаются в нём**. Для их удаления автор обращается к администратору канала. Если публикация уже выполняется, удаление данных ждёт окончания транзакции; опубликованный пост удалением базы не отзывается. Резервные копии и историю Telegram владелец обслуживает отдельно.
